# 抖音侧栏窗口（Windows）

这是 DSH 抖音侧栏插件的**测试版**，不是正式发布版本。它在 Windows 版 DSH 桌面应用里内嵌一个真实的抖音网页窗口，并通过修改 DSH 主程序让登录状态在重启后保留。

## 验证状态

- 已在一台 Windows 机器、DSH 0.2.2-rc.1 构建上完成真实安装验证，含三步：把官方原版归档换回、用本补丁重新打一遍、全档完整性校验；打出的归档 SHA-256 为 `844CABA6…D0CAF`，20519 个打包条目全部通过，重复执行返回「already patched」。
- 已在该机构建上完成**从零登录**验证：清空插件的会话目录后重新扫码登录，然后完全退出 DSH 再启动。退出期间直接读库确认 57 个抖音 Cookie（含 `sessionid`、`sid_tt`、`uid_tt`）已落盘，重启前后该库哈希完全一致，面板仍为登录态。
- **这些结果只证明该构建 + 该机器可用，不证明其他机器或后续版本可用。**补丁精确绑定了一份已知的 `lib/main.js` 内容哈希，构建内容不同会被直接拒绝而不是强行修改。
- 已用 README 里那条安装命令（`dsh plugin --profile … add github:puppetfreak2-cmyk/dsh-douyin-sidebar`）在全新临时 profile 里装过一次：pnpm 从 GitHub 拉下 tarball，装进 `node_modules\dsh-douyin-sidebar`，`lib\`、`patch\` 与根文件齐全；随后直接对这份**装进去的** `patch\install.ps1` 跑 `-CheckOnly`、打补丁、撤销，三步都正常（撤销后归档回到原版哈希）。
- 尚未在另一台干净 Windows 机器上做过同样的验证。

## 支持范围与功能

仅面向 Windows 版 DSH 桌面应用及其桌面浏览器桥；普通浏览器中打开 DSH 网页版不能使用该内嵌窗口。目标功能是打开和关闭侧栏中的真实 Electron `webview`，以及在适配的持久会话中保留登录。网页能否正常使用、登录能否持续，还取决于 DSH、抖音网页、账号和本机网络等条件，不作保证。

插件不内置代理、中继或 DNS 改写。新安全版补丁只识别特定主程序代码及完整性状态；版本号相同也不保证构建内容一致。它不是通用补丁，不应推断能支持其他 DSH 构建。

## 获取与安装

两步：

1. 装插件本体（和普通插件一样）：
   ```
   dsh plugin --profile <你的 profile 名> add github:puppetfreak2-cmyk/dsh-douyin-sidebar
   ```
2. 打持久化补丁。**先完全退出 DSH**，然后进入刚装好的插件目录，运行里面的脚本：

   ```
   cd <DSH 的 profile 目录>\profiles\<你的 profile 名>\node_modules\dsh-douyin-sidebar
   powershell -ExecutionPolicy Bypass -File patch\install.ps1
   ```

   profile 目录默认在 `%USERPROFILE%\.dsh`；如果你设过 `DSH_HOME` 环境变量，就在那个目录下（例如 `echo $env:DSH_HOME`）。

   脚本会自己找到 DSH、必要时请求管理员权限、备份原归档、打补丁、再回读校验。完成后从普通桌面重新打开 DSH。

想先确认兼容性、不改任何东西：`powershell -ExecutionPolicy Bypass -File patch\install.ps1 -CheckOnly`。

想撤销补丁：`powershell -ExecutionPolicy Bypass -File patch\install.ps1 -Restore`。撤销同样要关掉 DSH，会要求管理员权限。

撤销是**可验证的**，不是"拿最新的备份盖回去"：撤销前会先把每个备份按同样的规则重新打一遍补丁，只有重打结果与当前已装文件**逐字节相同**的那一份才会被采用；找不到这样的备份就拒绝动手，什么也不改。撤销后会另存一份当前已打补丁的归档，所以撤销本身也能再撤回来。

持久登录需要主程序配合；未经持久化适配的会话在 DSH 退出后不会保留。

## 补丁的作用与风险

- 补丁设计为修改 DSH 安装目录中的 `resources\app.asar`，而不是只修改插件目录。安装位置受系统保护时可能需要管理员权限；修改、备份和临时文件也会占用该目录的磁盘空间。
- 补丁仅针对工作区名精确为 `dsh-douyin-sidebar` 和 `dsh-douyin-webview` 的会话设计持久存储；前者使用 `<DSH_HOME>\browser\persistent\dsh-douyin-sidebar`，后者沿用历史目录 `<DSH_HOME>\browser\persistent\douyin`。两个目录不共享，新版侧栏首次使用通常需要重新登录。
- DSH 的插件共享客户端环境，桌面浏览器接口按工作区名而非插件身份区分会话。其他插件理论上可以请求同名工作区并访问该持久会话；不要在同一 DSH 环境运行不信任的插件。登录数据保存在本机，但本机账户、其他软件或插件的访问权限仍可能带来泄露风险。
- 补丁会检查主程序代码和归档完整性，备份和临时文件写入后会回读比对，替换前再次比对目标内容，替换后回读核验。检查失败时停止，不自动回滚；失败或中断后目标可能已经改变，备份也可能不完整，须人工核实。写入检查和进程检查不是锁，最后一次比对与替换之间仍有竞态，不能保证不覆盖其他进程的修改；操作期间应确保 DSH 及更新器等不会运行或修改该文件。这些检查也不能保证断电持久性、发现所有故障或保证 DSH 启动。
- **旧补丁不能直接升级到当前新安全版。**不要在旧补丁上强行覆盖或绕过不匹配检查；需先单独核实当前归档、DSH 版本及可信的原版文件，再制定恢复和验证方案。
- 自动撤销（`restore` / `-Restore`）可用，但只接受能被证明属于当前归档的备份（见上）。如果没有任何备份满足条件，它会拒绝并保持文件不变。
- DSH 更新可能覆盖补丁，也可能改变代码导致补丁不再适用。更新后不能假设重新运行补丁即可使用，必须重新核实兼容性和风险。

## 间歇性哈希失败

本机对大量归档条目连续计算摘要时曾观察到偶发不一致，随后对部分条目重复计算未复现。**根因尚未确定**；现有测试不能排除硬件、运行环境或软件等原因，也不能证明文件一定完好。

补丁代码在摘要有争议时使用原生计算重试及纯 JavaScript SHA-256 进行额外比对。这是降低误判的措施，不是对数据完整性或故障根因的证明；检查失败时应停止操作并调查，不应绕过校验。
